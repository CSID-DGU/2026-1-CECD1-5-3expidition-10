# 📚 Vision AI 기반 도서관 서고 관리 시스템

종합설계 5분반 3원정대 팀 프로젝트입니다.

순찰 로봇이 서가를 촬영했다고 가정하고, **촬영된 서가 이미지를 정상 상태의 서가 이미지와 비교해 이상을 탐지**하고, 그 결과를 **사서에게 대시보드로 전달**하는 시스템입니다. 실제 로봇은 범위에 포함하지 않으며, 로봇이 찍은 사진이 서버 DB의 **수신함**(`PATROL_PHOTO`)에 들어왔다고 가정하고(로봇 대신 `load_patrol_photos.py`가 사진을 넣음) 그 이후 과정을 다룹니다.

## 🌟 주요 기능
- **Vision AI 분석** (`MakeResult.py`, `app/`): YOLO 세그멘테이션으로 책등을 찾고, ResNet 특징으로 정상 서가 이미지의 책과 매칭합니다. 누움 · 기울어짐 · 뒤집힘 · 책등 안 보임 같은 **외형 이상**을 판별합니다.
- **서가 상태 판정** (`backend/analyzer.py`): Vision 결과, 가상 RFID, 도서 정보를 교차 검증해 **누락 · 오배가 · 상태이상 · 미분석 · 오배열 · 인식 실패** 같은 **위치 이상**을 판정합니다.
  - 판정 이름은 실제 도서관의 장서점검 용어(멘토 자료)를 따릅니다. 오배열 · 인식 실패 같은 영상 기반 판정은 우리 시스템에만 있는 기능입니다.
  - 도서 정보는 실제 도서관 시스템(KOLAS)의 테이블 구조(`BO_BOOK_TBL` 도서, `IDX_BO_TBL` 서지)를 따르고, 도서 ID는 **등록번호**(RFID 태그에 기록된 값)입니다.
  - 책 한 권을 놓쳐도 뒤의 책들이 줄줄이 오배열로 나오지 않도록 LIS(최장 증가 부분수열) 방식으로 판정합니다.
  - 인식이 크게 틀린 세션은 개별 알림 대신 **"재촬영 필요"** 로 안내합니다.
  - RFID로 읽힌 오배가 도서는 **원래 위치**("A구역 2번 책꽂이 3층 5번째")를 함께 알려 줍니다.
  - 책등이 안 보이는 책은 위치로 추정하지 않고 **알 수 없는 책**으로 판정합니다. RFID에는 있지만 사진에서 확인되지 않은 책을 후보로 보여 주며, 어떤 책인지 확정하지는 않습니다.
- **도서관 공간 관리**: 서가 위치를 **구역 → 책꽂이 → 층**으로 관리합니다. 사진 1장 = 책꽂이 한 층이며, 모든 결과가 "A구역 1번 책꽂이 3층"처럼 위치와 함께 표시됩니다.
  - 관리자는 대시보드의 **구조 편집**에서 구역 · 책꽂이 · 층을 직접 추가 · 수정 · 삭제합니다. 새 도서관은 빈 상태에서 시작해 하나씩 만들어 갑니다.
- **수신함 → 일괄 분석**: 순찰 사진은 DB의 수신함(`PATROL_PHOTO`, 사진째 저장)에 쌓이고, 사서가 대시보드에서 **버튼 한 번**으로 전부 분석합니다.
- **사서 화면**: 사서가 쓰는 순서대로 화면을 나눴습니다.
  - **첫 화면** (`backend/home.html`, `/`): 정리가 필요한 층 목록(문제 유형별 권수), 도서관 지도, 층별 상태 미니맵, 순찰 사진 일괄 분석 버튼.
  - **층 화면** (`backend/level.html`, `/level?shelf_id=`): 그 층의 순찰 사진 · 정상 상태 사진과 할 일 카드(책등 사진 포함). 오배가만 펼쳐 두고 나머지 알림은 접어 둡니다. "다음 층" 버튼으로 목록을 차례로 돕니다. 휴대폰 화면도 지원합니다.
  - **기존 대시보드** (`backend/dashboard_classic.html`, `/classic`, 상단 '관리' 메뉴): 한 화면에 모든 기능이 있는 이전 화면입니다. 기준 사진 · 구조 편집 · 사서 계정 · 지도 · 배가 위치 자동 배정 같은 관리 기능은 아직 여기서 합니다. 아래 설명은 이 화면 기준입니다.
  - **도서관 지도 / 서가 사진**: 평소에는 도서관 전체 지도를, 층을 고르면 그 층의 최근 순찰 사진을 보여줍니다.
  - **서가 선택**: 구역 탭 → 책꽂이별 층 미니맵에서 층마다 상태(조치 필요 / 재촬영 / 확인 필요 / 정상 / 미순찰)를 보고 바로 고릅니다.
  - 알림을 유형별로 묶어 심각도순(분실 위험 → 오배가 → 상태이상 → 오배열 → 외형 이상 → 확인 필요)으로 보여주고, 알림마다 **처리 완료 / 오탐**을 기록합니다.
  - **순찰 이력**에서 지난 결과를 다시 볼 수 있고, 새 순찰 결과는 20초마다 자동으로 반영됩니다.
  - 대시보드 · 리포트 · 로그인 화면은 **스마트폰 화면**에서도 쓸 수 있습니다.
- **일일 순찰 리포트** (`backend/report.html`): 날짜별로 구역 → 층마다 마지막 순찰 결과와 미처리 알림을 정리한 인쇄용 리포트입니다.
- **로그인 · 도서관별 분리**: 사서는 **도서관 ID + 아이디 + 비밀번호**로 로그인하고, 로그인한 도서관의 서가 · 순찰 기록 · 사진만 봅니다. 계정은 **관리자**(지도 · 기준 사진 · 도서관 구조 설정 가능)와 **일반 사서**로 나뉩니다.
- **정상 상태 기준 이미지 · 도서관 지도는 DB에 저장**: 컴퓨터를 바꿔도 DB만 있으면 그대로 쓸 수 있습니다.
- **배가 위치 자동 배정**: 책마다 위치를 넣지 않아도, 청구기호 순서와 기준 사진의 권수(또는 RFID 리더값)로 층과 순서를 만듭니다.

> RFID는 리더값이 없을 때 **가상 데이터**를 쓰고(`RFID_MODE=virtual`, 기본), 도서 정보는 실제 도서관 시스템과 같은 구조의 시연용 데이터입니다. `backend/db_create/library_data.sql`에 시연용 도서관 2곳이 있습니다.
> - `LIB001` 종합설계 시연 도서관: 구역 3개 × 책꽂이 5개 × 5층 = 75개 층. A구역 1번 책꽂이의 3개 층(위에서부터 A-01-5 · A-01-4 · A-01-3)에 청구기호 순서대로 58권이 배정되어 있습니다(가상 등록번호 `EM99…`, 가상 청구기호 `500.01 가001` 등). 나머지 층은 비어 있습니다
> - `LIB002` 두 번째 시연 도서관: **구조가 비어 있는 도서관**. 관리자로 로그인해 구조 편집을 처음부터 해 보거나, 도서관 분리를 확인하는 용도 (도서 없음)
>
> 실제 도서관 정보 시스템(ILS) · RFID 리더와 연동 가능한 구조로 설계했습니다.

## 🛠️ 설치 및 세팅

### 1. Python 패키지 (Python 3.10 이상)
```bash
pip install -r requirements.txt
```
> ⚠️ **백엔드 서버와 AI 분석은 같은 Python 환경을 써야 합니다.** 서버는 자신을 실행한 Python으로 AI 작업 프로세스(`MakeResult.py`)를 띄우기 때문에, AI 패키지(ultralytics, torch, pandas, scipy 등)가 없는 가상환경으로 서버를 띄우면 분석 단계에서 실패합니다.

### 2. AI 모델 파일
`model/yolo26l_1280_v3.pt`가 있어야 합니다. `.pt` 파일은 Git LFS로 관리하므로, Git LFS 없이 클론하면 1KB짜리 텍스트 파일만 받아집니다. 실행 중 `_pickle.UnpicklingError`가 나면 모델 파일을 직접 받아 덮어써 주세요.

### 3. 데이터베이스 (MySQL 8.0, Docker)
```bash
cd backend
docker-compose up -d   # 새로 만드는 경우: 스키마 + 가상 도서관/서가/도서 데이터 생성
python setup_db.py     # 항상 실행: 계정 · 시연용 기준 이미지를 넣고 최신 구조로 맞춤 (여러 번 실행해도 안전)
```
> - 새로 만든 DB에도 **`setup_db.py`를 꼭 한 번 실행**해야 로그인 계정과 기준 이미지가 생깁니다.
> - 코드를 새로 받았을 때(pull) DB 구조가 바뀌었을 수 있으니 `python setup_db.py`를 한 번 실행해 주세요. 기존 데이터는 지워지지 않으며, 예전 구조(도서관 구분 없는 `A-01-3` 등)는 `LIB001` 도서관으로 자동 이전됩니다.
> - **예전 도서 구조(`BOOK_MASTER`)의 DB**는 `setup_db.py`가 안내만 하고 멈춥니다. `python setup_db.py --convert`로 전환하세요. 전환하면 **예전 분석 기록(순찰 세션 · 판정 · 조치 기록)이 지워집니다**(도서 ID가 B001 → 등록번호로 바뀌어 맞지 않음). 전환 직전에 DB 전체를 `backups/v0.4/db/`에 자동 백업하고(docker 컨테이너 `library-mysql` 필요, 이름이 다르면 환경변수 `DB_CONTAINER`), 분석 전이던 수신함 폴더 사진은 DB로 옮깁니다.

비밀번호 같은 설정은 `backend/.env`에 둡니다. 없으면 시연용 기본값으로 동작하므로 개발할 때는 만들지 않아도 됩니다. 실제로 서비스할 때는 `backend/.env.example`을 `backend/.env`로 복사해 값을 바꾸세요. (`.env`는 git에 올라가지 않음, 환경변수가 있으면 환경변수가 우선)

| 설정 | 기본값 | 설명 |
| :--- | :--- | :--- |
| `DB_HOST`, `DB_PORT`, `DB_USER`, `DB_NAME` | `127.0.0.1`, `3306`, `root`, `library_ai_db` | DB 접속 정보 |
| `DB_PASSWORD` | `1234` | DB 비밀번호. `docker-compose.yml`도 같은 값을 씁니다 |
| `DEMO_ADMIN_PASSWORD`, `DEMO_LIBRARIAN_PASSWORD` | `admin1234`, `lib1234` | 시연용 계정의 비밀번호. `setup_db.py`가 계정을 처음 만들 때만 씁니다 |
| `RFID_MODE` | `virtual` | 순찰 사진에 RFID 리더값이 없을 때 `virtual`은 가상 RFID로 채우고, `real`은 채우지 않고 'RFID 미수신'으로 표시합니다 (영상으로만 판정, 가짜 누락 없음) |
| `PATROL_KEEP_COUNT` | `2` | 층마다 남길 순찰 횟수. 그 이전의 기록과 사진은 분석이 끝날 때 지웁니다. `0`이면 지우지 않습니다 |
| `COOKIE_SECURE` | `0` | `1`이면 로그인 쿠키를 HTTPS로만 보냅니다. HTTPS로 서비스할 때 켜세요. HTTP에서 켜면 로그인이 유지되지 않습니다 |

> - MySQL 포트는 이 컴퓨터(`127.0.0.1`)에서만 접속되도록 열려 있습니다. 다른 컴퓨터에서 DB에 직접 접속할 수 없습니다.
> - `DB_PASSWORD`와 `MYSQL_ROOT_PASSWORD`는 DB를 처음 만들 때만 적용됩니다. 이미 있는 DB의 비밀번호를 바꾸려면 MySQL에서 `ALTER USER`로 바꾼 뒤 `.env`를 고치세요.
> - 이미 있는 계정의 비밀번호는 대시보드 상단 **내 비밀번호**에서 본인이 바꿉니다. 관리자는 **사서 계정**에서 사서의 비밀번호도 바꿀 수 있습니다. (명령줄은 `manage_users.py`)
> - 같은 IP에서 로그인을 5분에 5번 실패하면 5분 동안 로그인을 막습니다. (서버를 재시작하면 풀림)
> - **DB 데이터는 docker 볼륨 `library_mysql_data`에 있습니다.** 컨테이너를 다시 만들어도 유지되지만, **`docker compose down -v`를 실행하면 모든 데이터가 지워집니다.** 평소에는 `-v` 없이 `docker compose down`을 쓰세요.
> - **예전에 만든 DB가 있는 컴퓨터**는 이름 없는 볼륨에 데이터가 있습니다. 이 변경을 받고 그대로 `docker compose up -d`를 하면 **빈 새 볼륨으로 시작해서 기존 데이터가 안 보입니다.** (지워지지는 않음) 아래처럼 먼저 옮기세요.
>   ```bash
>   docker inspect library-mysql --format "{{json .Mounts}}"   # /var/lib/mysql의 Name이 옛 볼륨 이름
>   docker compose stop db
>   docker volume create --label com.docker.compose.project=library-project --label com.docker.compose.volume=library_mysql_data library_mysql_data
>   docker run --rm --entrypoint sh -v <옛 볼륨 이름>:/from -v library_mysql_data:/to mysql:8.0 -c "cp -a /from/. /to/"
>   docker compose up -d
>   ```
>   옛 데이터가 필요 없으면 `docker compose up -d` 뒤 `python setup_db.py`만 실행하면 됩니다.

### 외부에서 접속하기 (Cloudflare Tunnel)
> 서버 실행부터 터널, 문제 해결까지의 전체 순서는 [서버 실행 · 외부 접속 설명서](docs/server_guide.md)에 있습니다.

노트북 · 스마트폰 등 다른 기기에서는 Cloudflare Quick Tunnel로 접속합니다. 포트를 열 필요가 없고 계정 · 도메인 없이 HTTPS 주소가 만들어집니다.

1. `backend/.env`의 시연 계정 비밀번호를 기본값이 아닌 값으로 바꾸고 `COOKIE_SECURE=1`로 둡니다. (DB의 비밀번호도 함께 바꿔야 합니다)
2. 서버를 켠 뒤 다른 터미널에서 터널을 켭니다. 출력에 나오는 `https://….trycloudflare.com` 주소로 접속합니다.
   ```bash
   cloudflared tunnel --no-autoupdate --url http://127.0.0.1:8000
   ```

> - **터널을 다시 켜면 주소가 바뀝니다.** 임시 주소라 실제 운영용이 아닙니다. 고정 주소가 필요하면 도메인을 연결한 Named Tunnel을 쓰세요.
> - 서버와 터널을 켠 컴퓨터가 꺼지거나 절전되면 접속이 끊깁니다.
> - 주소를 아는 사람은 누구나 로그인 화면에 들어올 수 있습니다.

### 4. 계정 (시연용)
`setup_db.py`가 만드는 시연용 계정입니다. 아래 비밀번호는 **이 컴퓨터에서만 쓰는 기본값**입니다. 외부에 공개하기 전에는 반드시 바꾸세요.

| 도서관 ID | 아이디 | 비밀번호 | 권한 |
| :--- | :--- | :--- | :--- |
| `LIB001` | `admin` | `admin1234` | 관리자 |
| `LIB001` | `librarian` | `lib1234` | 일반 사서 |
| `LIB002` | `admin` | `admin1234` | 관리자 |

- **관리자**: 일반 사서 기능 + 도서관 지도 등록 · 정상 상태 기준 사진 등록/교체/되돌리기/일괄 갱신 · 도서관 구조 편집 · **일반 사서 계정 추가/삭제 · 비밀번호 변경**
- **공통**: 상단 **내 비밀번호**에서 본인 비밀번호 변경 (현재 비밀번호 확인, 다른 기기의 로그인은 끊어짐)
- **일반 사서**: 순찰 사진 일괄 분석, 결과 확인, 알림 처리 완료 · 오탐 기록 (누가 처리했는지 함께 기록됨), 리포트

**일반 사서 계정**은 관리자가 대시보드 오른쪽 위 **사서 계정** 버튼에서 추가 · 삭제하고 비밀번호를 바꿉니다. (자기 도서관 계정만 보이고, 관리자 계정은 지우거나 바꿀 수 없음. 비밀번호를 바꾸면 그 사서의 기존 로그인이 끊어짐)
- 추가: 이름 · 아이디(영문 · 숫자 3~30자) · 비밀번호(8자 이상). 만든 아이디 · 비밀번호를 사서에게 전달합니다.
- 삭제: 그 계정으로는 바로 로그인할 수 없게 됩니다(로그인 중이던 화면도 끊김). 그 사서가 알림을 처리한 기록이 있으면, 이력에 '누가 처리했는지'가 남도록 계정 정보는 숨긴 채 보관합니다. 같은 아이디는 다시 만들 수 있습니다.

관리자 계정 추가, 다른 관리자의 비밀번호 변경(잊어버렸을 때 포함), 새 도서관은 `backend/manage_users.py`(명령줄)로 합니다.
```bash
cd backend
python manage_users.py list LIB001                     # 계정 목록
python manage_users.py add LIB001 hong "홍길동"          # 일반 사서 추가 (비밀번호는 입력 받음)
python manage_users.py add LIB001 boss "관리자2" --admin # 관리자 추가
python manage_users.py password LIB001 hong             # 비밀번호 변경 (기존 로그인 해제)
python manage_users.py disable LIB001 hong              # 로그인 막기 / enable 로 다시 허용
python manage_users.py create-library LIB003 "새 도서관"  # 새 도서관 + 첫 관리자(admin) (구조는 비어 있음)
```

### 5. 정상 상태 기준 이미지 (DB 저장)
분석할 때 각 층의 사진은 **그 층의 정상 상태 사진**과 비교됩니다. 기준 이미지는 **DB(`NORMAL_IMAGE` 테이블)** 에 저장되므로, 다른 컴퓨터에서 서버를 띄워도 같은 DB를 쓰면 다시 옮길 필요가 없습니다.
- **대시보드에서 등록 (관리자)**: 층을 선택하고 **정상 상태** 탭에서 등록합니다. 한 층에 한 장(현재 기준)이며, 이미지(jpg · png)가 아닌 파일은 거절됩니다.
  - **기준 사진 올리기 / 교체**: 사진 파일을 직접 올립니다.
  - **이 층만 최근 순찰 사진으로**: 서가를 정리한 직후 순찰했다면, 그 순찰 사진을 이 층의 기준으로 지정합니다. (조건이 맞지 않으면 이유를 경고로 보여 줌)
  - **기준 사진 일괄 갱신** (서가 선택 카드 아래): 최근 순찰 사진을 기준으로 써도 되는 층(맵의 **파란 점** ●)을 한꺼번에 바꿉니다. 대상: 최근 순찰의 인식 신뢰도가 정상이고, **미비치(대출 중 등) 도서가 없고**(순찰 당시 · 현재 모두), 알림이 없거나 전부 '오탐'인 층. '처리 완료' 알림이 있던 순찰은 정리 전 사진이므로 제외됩니다.
  - **이전 기준 사진으로 되돌리기**: 교체 · 삭제된 이전 사진도 층마다 최근 10장까지 DB에 보관되어 되돌릴 수 있습니다.
- **처음 DB를 만들 때**: `setup_db.py`가 `backend/db_create/seed/normal_images/<도서관>/<구역>/<책꽂이>/<층>.jpg`의 사진을 기준 이미지가 없는 층에 넣습니다. (현재 `LIB001`의 3개 층. 이미 기준 이미지가 있는 층은 건드리지 않음)
- 기준 이미지가 없는 층은 분석이 실패하고, 대시보드 '정상 상태' 탭에서 등록하라고 안내합니다. 도서는 있는데 기준 사진이 없는 층은 서가 맵과 '확인이 필요한 층' 목록에 **기준 사진 없음**으로 표시됩니다.
- 기준 사진의 분석 결과도 DB(`NORMAL_IMAGE_ANALYSIS`)에 저장해 재사용합니다. 기준 사진을 등록 · 교체 · 지정 · 되돌릴 때와 서버를 켤 때 미리 분석하므로, 순찰 사진 분석은 기준 사진을 다시 분석하지 않습니다. 기준 사진이나 AI 코드 · 모델이 바뀌면 자동으로 새로 분석합니다.
- 서버는 분석할 때 그 층의 기준 이미지를 DB에서 꺼내 씁니다.

### 2. 순찰 사진을 수신함에 넣기 (로봇 대신)
완성된 시스템에서는 로봇이 도서관을 돌며 층마다 사진을 찍어 서버 DB의 **수신함**(`PATROL_PHOTO`)에 넣습니다. 로봇은 이 프로젝트 범위 밖이므로, **`load_patrol_photos.py`가 사진 폴더를 읽어 로봇 대신 수신함에 넣습니다.** 이 단계에서는 사진을 쌓아 두기만 하고 분석하지 않습니다.

**사진 폴더 구조**: 도서관 폴더 안에 구역 / 책꽂이별 폴더를 두고, **층 코드로 시작하는 이름**으로 넣습니다.
```
LIB001/                       # 도서관 (폴더 이름 = 도서관 ID, 다르면 --library로 지정)
├── A/                        # 구역
│   ├── A-01/                 # 책꽂이
│   │   ├── A-01-3.jpg        # A구역 1번 책꽂이 3층 (A-01-3_아침.jpg처럼 뒤에 아무거나 붙여도 됨)
│   │   └── ...
│   └── A-02/ ...
└── B/ ...
```
```bash
python backend/load_patrol_photos.py LIB001          # 프로젝트 루트에서. 촬영 시각 = 파일 수정 시각 (--now: 지금 시각)
```
- 폴더가 맞지 않거나, 도서가 없는 층이거나, 사진(jpg · png)이 아닌 파일은 넣지 않고 이유를 출력합니다. 원본 파일은 지우지 않습니다.
- **한 층에 분석 전 사진은 가장 최신 한 장만 남습니다.** 같은 층의 사진을 또 넣으면 촬영 시각이 늦은 사진이 앞 사진을 덮어씁니다(분석 대기 · 실패 사진만, 분석이 시작된 사진은 그대로). 모두 넣으려면 `--keep-all`을 씁니다.
- 같은 사진 · 같은 RFID 리더값이 아직 분석 전이면 다시 넣지 않습니다. 분석이 끝난 뒤 같은 사진을 다시 넣으면 새 순찰 사진으로 들어갑니다.

**RFID 리더값**: 사진 옆에 `<사진 이름>.rfid.json`(예: `A-01-3.rfid.json`)이 있으면 리더값으로 함께 넣습니다. 내용은 등록번호 목록 또는 `[{"reg_no": "...", "rssi": -45}]`이고, `[]`는 '읽은 태그 없음'이라는 실제 결과입니다. 수신함에 이미 있는 사진에는 `POST /api/patrol/photos/{photo_id}/rfid`로 붙일 수 있습니다. 대시보드 상단에 그 순찰의 RFID 출처(RFID 리더 / 가상 RFID / RFID 미수신)가 표시됩니다.

> 2026-11 이전에 만든 시연 DB는 책이 배정된 층이 달라 `setup_db.py`만으로 맞지 않습니다. 필요한 기록을 백업한 뒤 `backend`에서 `docker compose down -v` → `docker compose up -d` → `python setup_db.py`로 새로 만드세요.

**시연 시나리오**: 오배가 · RFID 미인식 · 책등 안 보임 등이 나오는 사진과 RFID 묶음은 [backend/test_data/scenarios](backend/test_data/scenarios/README.md)에 있습니다.

**테스트용 순찰 사진**: 저장소 맨 위의 `LIB001/` 폴더에 3개 층의 사진이 위 구조로 들어 있어, 위 명령 한 줄로 바로 일괄 분석할 수 있습니다. 이 3개 층의 도서 목록(`library_data.sql`)과 정상 기준 사진(`backend/db_create/seed/normal_images/`)은 `setup_db.py`가 넣어 줍니다.

| 층 | 사진 | 도서 | 참고 |
|---|---|---|---|
| A구역 1번 책꽂이 5층 | `LIB001/A/A-01/A-01-5.jpg` | 13권 | 13번 「지텔프 LEVEL 2 공식 기출문제집」은 **미태깅 도서** 예시 (RFID 없이 영상으로만 판정) |
| A구역 1번 책꽂이 4층 | `LIB001/A/A-01/A-01-4.jpg` | 31권 | |
| A구역 1번 책꽂이 3층 | `LIB001/A/A-01/A-01-3.jpg` | 14권 | |

> 이 사진들은 각 층의 정상 기준 사진과 같은 사진이라, "정리된 서가에서 알림이 나오지 않는지"를 확인하는 용도입니다. 오배열 · 누락 같은 이상 탐지는 기준과 다르게 찍은 사진으로 확인해야 합니다.

### 3. 대시보드에서 일괄 분석 → 확인 (사서 역할)
브라우저에서 http://127.0.0.1:8000 에 접속해 **도서관 ID · 아이디 · 비밀번호**로 로그인합니다. (로그인은 12시간 유지, 오른쪽 위 **로그아웃**)
1. 맨 위 **순찰 사진 수신함** 바에 "분석 대기 N장 (A구역 · B구역 …)"이 보이면 **순찰 사진 일괄 분석** 버튼을 누릅니다.
2. 수신함의 사진이 **구역 → 책꽂이 → 층 → 촬영 시각 순서**로 한 장씩 AI 분석 → 상태 판정됩니다. 진행률과 지금 분석 중인 위치가 표시되고, 끝날 때마다 서가 현황이 갱신됩니다. (기다리지 않고 자리를 비워도 됩니다)
3. 분석이 끝나면 알림판의 **확인이 필요한 층** 목록(우선순위순)이나 왼쪽 **서가 선택**에서 층을 고릅니다. 그 층의 최근 순찰 사진과 알림이 열립니다.
4. 알림을 확인한 뒤 **처리 완료** 또는 **오탐**을 누르면 기록됩니다. (되돌리기 가능)

- 분석에 실패한 사진은 수신함에 '실패'로 남아 다음 일괄 분석 때 다시 시도됩니다. 분석 중에 서버가 재시작되면 진행 중이던 사진은 '분석 대기'로 되돌아갑니다.
- **순찰 이력**: 지난 순찰을 누르면 그때의 결과와 사진을 다시 볼 수 있습니다. 층마다 **최근 2회**만 보관합니다(`PATROL_KEEP_COUNT`). 분석이 끝나면 그 이전 순찰의 판정 · 조치 기록과 사진이 지워지고, 일일 리포트에서도 볼 수 없습니다.
- **일일 리포트**: 상단의 **일일 리포트** 버튼(또는 http://127.0.0.1:8000/report)에서 날짜를 골라 조회 · 인쇄할 수 있습니다.
- **도서관 지도** (관리자): '도서관 지도' 탭 아래 **지도 올리기 / 변경 / 삭제** 버튼으로 관리합니다. (jpg · png · webp, 도서관별로 DB에 저장)
- **배가 위치 자동 배정** (관리자): '서가 선택' 카드 아래의 버튼을 누릅니다. 청구기호순 도서 목록을 층의 배가 순서대로 기준 사진 권수만큼 잘라 배정안을 만듭니다.
  - RFID 리더값이 있는 층은 읽힌 책으로 정합니다. 미태깅 도서는 청구기호 위치에 끼워 넣습니다.
  - 층마다 첫 책 · 마지막 책과 기준 사진의 책등을 비교해, 틀린 층의 권수를 고치고 **다시 계산**한 뒤 **이 배정으로 저장**합니다.
  - 잘못 저장했으면 **이전 배정으로 되돌리기**를 누릅니다. 마지막 저장 직전의 배정 한 벌만 보관합니다.
  - 기준 사진이 있는 층만 배정합니다. 기준 사진을 바꾸거나 책이 크게 바뀌면 다시 실행하세요. 기준 사진의 권수와 연결된 책 수가 다르면 알림판에 경고가 나옵니다.
  - 청구기호가 없는 책은 배정되지 않습니다. 저장 전에 화면 위쪽의 '배정되지 못한 책' · '청구기호가 없어 뺀 책' 수를 확인하세요. 저장하면 도서관의 배가 위치를 새로 만들고, 지난 순찰 결과는 바뀌지 않습니다.
- **도서관 구조 편집** (관리자): '서가 선택' 카드 오른쪽 위 **구조 편집**을 누르면 편집 모드가 됩니다. 구조가 비어 있는 도서관에 관리자가 처음 접속하면 바로 편집 모드로 열립니다.
  - **+ 구역**: 구역 코드(A, B …, 만든 뒤 변경 불가) · 이름 · 위치. 원하면 책꽂이 N개 × M층을 한 번에 함께 만듭니다.
  - **+ 책꽂이**: 번호(기본 = 마지막 번호 + 1) · 설명 · 층 수. **+ 층**: 그 책꽂이 맨 위에 한 층 추가 (층 번호는 맨 아래가 1층).
  - **구역 수정** / 책꽂이 번호 / 층 칸을 누르면 이름(설명)을 고치거나 지울 수 있습니다.
  - 지우기 규칙: 순찰 기록 · 배가된 도서 · 수신함 사진이 있는 층은 지울 수 없고, 층은 번호가 비지 않도록 맨 위 층부터 지웁니다. 구역 · 책꽂이는 안의 층을 모두 지울 수 있을 때만 통째로 지워집니다(층의 기준 사진도 함께 삭제).
  - 새로 만든 층은 **도서 없음** 상태입니다. 도서 목록(정답지)이 `library_data.sql`에 등록된 층만 분석할 수 있습니다.

## ⚠️ 현재 알려진 제약
- **정상 이미지의 인식 누락이 도서 연결에 영향을 줍니다.** AI가 돌려주는 책 ID(`B001`~)는 "정상 이미지에서 왼쪽부터 n번째로 인식된 책"이고, 서버는 이것을 그 층의 n번째 배가 도서(`BOOK_LOCATION.correct_order` = n)의 등록번호로 바꿉니다. 정상 이미지에서 책이 하나라도 인식되지 않으면 그 뒤 번호가 한 칸씩 밀려 다른 책의 등록번호와 연결됩니다.
- **미비치 판단은 자료상태 코드 하나로만 합니다.** `WORKING_STATUS`가 `BOL112N`이면 비치중, 나머지는 모두 미비치(대출 중 등)로 봅니다. 멘토님께 받은 코드표가 아직 없어 예시 데이터에서 추정한 기준입니다.
- **분석 작업 기록은 서버 메모리에만 있습니다.** 분석 중에 서버를 재시작하면 진행 중이던 작업은 사라집니다. (완료된 결과는 DB에 남음)
- **관리자 계정 관리와 잊어버린 관리자 비밀번호 재설정은 명령줄(`manage_users.py`)로만** 할 수 있습니다. 서버는 HTTP로 동작하므로, 실제 배포할 때는 HTTPS(리버스 프록시 등) 뒤에 두어야 합니다.
- **판정 기준값은 임시로 정한 값입니다.** 매칭 유사도, 인식 품질 기준 등은 AI 모델의 정확도가 확정되면 실제 결과를 보고 조정해야 합니다. (`backend/analyzer.py` 상단 상수)
