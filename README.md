# 📚 Vision AI 기반 도서관 서고 관리 시스템

종합설계 5분반 3원정대 팀 프로젝트입니다.

순찰 로봇이 서가를 촬영했다고 가정하고, **촬영된 서가 이미지를 정상 상태의 서가 이미지와 비교해 이상을 탐지**하고, 그 결과를 **사서에게 대시보드로 전달**하는 시스템입니다. 실제 로봇은 범위에 포함하지 않으며, 로봇이 찍은 사진이 서버의 **수신함 폴더**에 들어왔다고 가정하고(사진을 폴더에 직접 넣음) 그 이후 과정을 다룹니다.

## 🌟 주요 기능
- **Vision AI 분석** (`ach/`): YOLO 세그멘테이션으로 책등을 찾고, ResNet 특징으로 정상 서가 이미지의 책과 매칭합니다. 누움 · 기울어짐 · 뒤집힘 · 종이 끼임 같은 **외형 이상**을 판별합니다.
- **서가 상태 판정** (`backend/analyzer.py`): Vision 결과, 가상 RFID, 가상 서가 정보를 교차 검증해 **오배열 · 누락 · 오배가 · 인식 실패** 같은 **위치 이상**을 판정합니다.
  - 책 한 권을 놓쳐도 뒤의 책들이 줄줄이 오배열로 나오지 않도록 LIS(최장 증가 부분수열) 방식으로 판정합니다.
  - 인식이 크게 틀린 세션은 개별 알림 대신 **"재촬영 필요"** 로 안내합니다.
- **도서관 공간 관리**: 서가 위치를 **구역 → 책꽂이 → 층**으로 관리합니다. 사진 1장 = 책꽂이 한 층이며, 모든 결과가 "A구역 1번 책꽂이 3층"처럼 위치와 함께 표시됩니다.
  - 관리자는 대시보드의 **구조 편집**에서 구역 · 책꽂이 · 층을 직접 추가 · 수정 · 삭제합니다. 새 도서관은 빈 상태에서 시작해 하나씩 만들어 갑니다.
- **수신함 폴더 → 일괄 분석**: 순찰 사진은 서버의 수신함 폴더(`backend/patrol_inbox/`)에 쌓이고, 사서가 대시보드에서 **버튼 한 번**으로 전부 분석합니다.
- **사서 대시보드** (`backend/dashboard.html`): 순찰 사진 일괄 분석과 결과 확인을 하는 화면입니다.
  - **도서관 지도 / 서가 사진**: 평소에는 도서관 전체 지도를, 층을 고르면 그 층의 최근 순찰 사진을 보여줍니다.
  - **서가 선택**: 구역 탭 → 책꽂이별 층 미니맵에서 층마다 상태(조치 필요 / 재촬영 / 확인 필요 / 정상 / 미순찰)를 보고 바로 고릅니다.
  - 알림을 유형별로 묶어 심각도순(분실 위험 → 오배가 → 오배열 → 외형 이상 → 확인 필요)으로 보여주고, 알림마다 **처리 완료 / 오탐**을 기록합니다.
  - **순찰 이력**에서 지난 결과를 다시 볼 수 있고, 새 순찰 결과는 20초마다 자동으로 반영됩니다.
- **일일 순찰 리포트** (`backend/report.html`): 날짜별로 구역 → 층마다 마지막 순찰 결과와 미처리 알림을 정리한 인쇄용 리포트입니다.
- **로그인 · 도서관별 분리**: 사서는 **도서관 ID + 아이디 + 비밀번호**로 로그인하고, 로그인한 도서관의 서가 · 순찰 기록 · 사진만 봅니다. 계정은 **관리자**(지도 · 기준 사진 · 도서관 구조 설정 가능)와 **일반 사서**로 나뉩니다.
- **정상 상태 기준 이미지 · 도서관 지도는 DB에 저장**: 컴퓨터를 바꿔도 DB만 있으면 그대로 쓸 수 있습니다.

> RFID와 서가(도서) 정보는 현재 **가상 데이터**입니다. `backend/db_create/library_data.sql`에 시연용 도서관 2곳이 있습니다.
> - `LIB001` 종합설계 시연 도서관: 구역 3개 × 책꽂이 5개 × 5층 = 75개 층. 도서는 정상 상태 이미지를 찍은 **A구역 1번 책꽂이 3층**(`LIB001-A-01-3`)에만 13권
> - `LIB002` 두 번째 시연 도서관: **구조가 비어 있는 도서관**. 관리자로 로그인해 구조 편집을 처음부터 해 보거나, 도서관 분리를 확인하는 용도 (도서 없음)
>
> 나중에 실제 도서관 정보 시스템(ILS)과 연동할 예정입니다.

## 🛠️ 설치 및 세팅

### 1. Python 패키지 (Python 3.10 이상)
```bash
pip install -r requirements.txt
```
> ⚠️ **백엔드 서버와 AI 분석은 같은 Python 환경을 써야 합니다.** 서버는 자신을 실행한 Python으로 `ach/JsonTesting.py`를 돌리기 때문에, AI 패키지(ultralytics, torch)가 없는 가상환경으로 서버를 띄우면 분석 단계에서 실패합니다.

### 2. AI 모델 파일
`ach/model/yolo11m_seg_v5.pt`가 있어야 합니다. `.pt` 파일은 Git LFS로 관리하므로, Git LFS 없이 클론하면 1KB짜리 텍스트 파일만 받아집니다. 실행 중 `_pickle.UnpicklingError`가 나면 모델 파일을 직접 받아 덮어써 주세요.

### 3. 데이터베이스 (MySQL 8.0, Docker)
```bash
cd backend
docker-compose up -d   # 새로 만드는 경우: 스키마 + 가상 도서관/서가/도서 데이터 생성
python setup_db.py     # 항상 실행: 계정 · 시연용 기준 이미지를 넣고 최신 구조로 맞춤 (여러 번 실행해도 안전)
```
> - 새로 만든 DB에도 **`setup_db.py`를 꼭 한 번 실행**해야 로그인 계정과 기준 이미지가 생깁니다.
> - 코드를 새로 받았을 때(pull) DB 구조가 바뀌었을 수 있으니 `python setup_db.py`를 한 번 실행해 주세요. 기존 데이터는 지워지지 않으며, 예전 구조(도서관 구분 없는 `A-01-3` 등)는 `LIB001` 도서관으로 자동 이전됩니다.

DB 접속 정보는 `backend/config.py`에 있고, 환경변수(`DB_HOST`, `DB_USER`, `DB_PASSWORD`, `DB_NAME`, `DB_PORT`)로 바꿀 수 있습니다.

### 4. 계정 (시연용)
`setup_db.py`가 만드는 시연용 계정입니다. **실제 배포 전에는 반드시 비밀번호를 바꾸세요.**

| 도서관 ID | 아이디 | 비밀번호 | 권한 |
| :--- | :--- | :--- | :--- |
| `LIB001` | `admin` | `admin1234` | 관리자 |
| `LIB001` | `librarian` | `lib1234` | 일반 사서 |
| `LIB002` | `admin` | `admin1234` | 관리자 |

- **관리자**: 일반 사서 기능 + 도서관 지도 등록 · 정상 상태 기준 사진 등록/교체/되돌리기/일괄 갱신 · 도서관 구조 편집 · **일반 사서 계정 추가/삭제**
- **일반 사서**: 순찰 사진 일괄 분석, 결과 확인, 알림 처리 완료 · 오탐 기록 (누가 처리했는지 함께 기록됨), 리포트

**일반 사서 계정**은 관리자가 대시보드 오른쪽 위 **사서 계정** 버튼에서 추가 · 삭제합니다. (자기 도서관 계정만 보이고, 관리자 계정은 지울 수 없음)
- 추가: 이름 · 아이디(영문 · 숫자 3~30자) · 비밀번호(8자 이상). 만든 아이디 · 비밀번호를 사서에게 전달합니다.
- 삭제: 그 계정으로는 바로 로그인할 수 없게 됩니다(로그인 중이던 화면도 끊김). 그 사서가 알림을 처리한 기록이 있으면, 이력에 '누가 처리했는지'가 남도록 계정 정보는 숨긴 채 보관합니다. 같은 아이디는 다시 만들 수 있습니다.

관리자 계정 · 비밀번호 변경 · 새 도서관은 `backend/manage_users.py`(명령줄)로 합니다.
```bash
cd backend
python manage_users.py list LIB001                     # 계정 목록
python manage_users.py add LIB001 hong "홍길동"          # 일반 사서 추가 (비밀번호는 입력 받음)
python manage_users.py add LIB001 boss "관리자2" --admin # 관리자 추가
python manage_users.py password LIB001 hong             # 비밀번호 변경 (기존 로그인 해제)
python manage_users.py disable LIB001 hong              # 로그인 막기 / enable 로 다시 허용
python manage_users.py create-library LIB003 "새 도서관"  # 새 도서관 + 첫 관리자(admin) (구조는 비어 있음)
```

### 5. 정상 상태 기준 이미지 (DB 저장)
분석할 때 각 층의 사진은 **그 층의 정상 상태 사진**과 비교됩니다. 기준 이미지는 **DB(`NORMAL_IMAGE` 테이블)** 에 저장되므로, 다른 컴퓨터에서 서버를 띄워도 같은 DB를 쓰면 다시 옮길 필요가 없습니다.
- **대시보드에서 등록 (관리자)**: 층을 선택하고 **정상 상태** 탭에서 등록합니다. 한 층에 한 장(현재 기준)이며, 이미지(jpg · png)가 아닌 파일은 거절됩니다.
  - **기준 사진 올리기 / 교체**: 사진 파일을 직접 올립니다.
  - **이 층만 최근 순찰 사진으로**: 서가를 정리한 직후 순찰했다면, 그 순찰 사진을 이 층의 기준으로 지정합니다. (조건이 맞지 않으면 이유를 경고로 보여 줌)
  - **기준 사진 일괄 갱신** (서가 선택 카드 아래): 최근 순찰 사진을 기준으로 써도 되는 층(맵의 **파란 점** ●)을 한꺼번에 바꿉니다. 대상: 최근 순찰의 인식 신뢰도가 정상이고, **대출 중인 도서가 없고**(순찰 당시 · 현재 모두), 알림이 없거나 전부 '오탐'인 층. '처리 완료' 알림이 있던 순찰은 정리 전 사진이므로 제외됩니다.
  - **이전 기준 사진으로 되돌리기**: 교체 · 삭제된 이전 사진도 층마다 최근 10장까지 DB에 보관되어 되돌릴 수 있습니다.
- **처음 DB를 만들 때**: `setup_db.py`가 `backend/db_create/seed/normal_images/<도서관>/<구역>/<책꽂이>/<층>.jpg`의 사진을 기준 이미지가 없는 층에 넣습니다. (현재 `LIB001/A/A-01/A-01-3.jpg` 1장. 이미 기준 이미지가 있는 층은 건드리지 않음)
- 기준 이미지가 없는 층은 분석이 실패하고, 대시보드 '정상 상태' 탭에서 등록하라고 안내합니다. 도서는 있는데 기준 사진이 없는 층은 서가 맵과 '확인이 필요한 층' 목록에 **기준 사진 없음**으로 표시됩니다.
- 서버는 분석할 때 그 층의 기준 이미지를 DB에서 꺼내 작업 폴더(`backend/.normal_work`)에 쓰고, `NORMAL_DIR` 환경변수로 `ach/JsonTesting.py`에 넘깁니다. 환경변수 없이 `JsonTesting.py`를 직접 실행하면 예전처럼 `ach/dataset/normal`을 씁니다.

## 🚀 실행 방법

```bash
cd backend
python -m uvicorn main:app --reload
```

### 2. 순찰 사진을 수신함 폴더에 넣기
완성된 시스템에서는 로봇이 도서관을 돌며 층마다 사진을 찍어 서버의 **수신함 폴더**에 넣습니다. 로봇은 이 프로젝트 범위 밖이므로, **사진을 수신함 폴더에 직접 넣어** 로봇이 넣은 것으로 가정합니다. 이 단계에서는 사진을 쌓아 두기만 하고 분석하지 않습니다.

**수신함 폴더 구조**: 사진은 도서관 / 구역 / 책꽂이별 폴더에 **층 코드로 시작하는 이름**으로 넣습니다. 폴더는 서버가 미리 만들어 둡니다.
```
backend/patrol_inbox/
├── LIB001/                   # 도서관
│   ├── A/                    # 구역
│   │   ├── A-01/             # 책꽂이
│   │   │   ├── A-01-3_20261003_093000_1a2b3c.jpg   # A구역 1번 책꽂이 3층
│   │   │   └── ...
│   │   └── A-02/ ...
│   ├── B/ ...
│   └── C/ ...
└── LIB002/ ...
```
예: `LIB001/A/A-01/A-01-3.jpg`, `A-01-3_아침.jpg`처럼 넣으면 대시보드가 자동으로 수신함 사진으로 등록합니다(촬영 시각 = 파일 수정 시각). 폴더가 맞지 않거나, 도서가 없는 층이거나, 사진이 아닌 파일은 등록하지 않고 대시보드에 이유를 표시합니다. 분석이 끝난 사진은 수신함에서 지워집니다(원본은 세션 보관소에 남음). 같은 이름으로 다시 넣으면 새 순찰 사진으로 등록됩니다.

**테스트용 순찰 사진**: 저장소 맨 위의 `LIB001/` 폴더에 4개 층의 사진이 수신함과 같은 구조로 들어 있습니다. 폴더째 수신함에 복사하면 바로 일괄 분석할 수 있습니다. 이 4개 층의 도서 목록(`library_data.sql`)과 정상 기준 사진(`backend/db_create/seed/normal_images/`)은 `setup_db.py`가 넣어 줍니다.
```bash
cp -r LIB001 backend/patrol_inbox/            # Windows PowerShell: Copy-Item -Recurse LIB001 backend\patrol_inbox
```

### 3. 대시보드에서 일괄 분석 → 확인 (사서 역할)
브라우저에서 http://127.0.0.1:8000 에 접속해 **도서관 ID · 아이디 · 비밀번호**로 로그인합니다. (로그인은 12시간 유지, 오른쪽 위 **로그아웃**)
1. 맨 위 **순찰 사진 수신함** 바에 "분석 대기 N장 (A구역 · B구역 …)"이 보이면 **순찰 사진 일괄 분석** 버튼을 누릅니다.
2. 수신함의 사진이 **구역 → 책꽂이 → 층 → 촬영 시각 순서**로 한 장씩 AI 분석 → 상태 판정됩니다. 진행률과 지금 분석 중인 위치가 표시되고, 끝날 때마다 서가 현황이 갱신됩니다. (기다리지 않고 자리를 비워도 됩니다)
3. 분석이 끝나면 알림판의 **확인이 필요한 층** 목록(우선순위순)이나 왼쪽 **서가 선택**에서 층을 고릅니다. 그 층의 최근 순찰 사진과 알림이 열립니다.
4. 알림을 확인한 뒤 **처리 완료** 또는 **오탐**을 누르면 기록됩니다. (되돌리기 가능)

- 분석에 실패한 사진은 수신함에 남아 다음 일괄 분석 때 다시 시도됩니다. 분석 중에 서버가 재시작되면 진행 중이던 사진은 '분석 대기'로 되돌아갑니다.
- **순찰 이력**: 지난 순찰을 누르면 그때의 결과와 사진을 다시 볼 수 있습니다.
- **일일 리포트**: 상단의 **일일 리포트** 버튼(또는 http://127.0.0.1:8000/report)에서 날짜를 골라 조회 · 인쇄할 수 있습니다.
- **도서관 지도** (관리자): '도서관 지도' 탭 아래 **지도 올리기 / 변경 / 삭제** 버튼으로 관리합니다. (jpg · png · webp, 도서관별로 DB에 저장)
- **도서관 구조 편집** (관리자): '서가 선택' 카드 오른쪽 위 **구조 편집**을 누르면 편집 모드가 됩니다. 구조가 비어 있는 도서관에 관리자가 처음 접속하면 바로 편집 모드로 열립니다.
  - **+ 구역**: 구역 코드(A, B …, 만든 뒤 변경 불가) · 이름 · 위치. 원하면 책꽂이 N개 × M층을 한 번에 함께 만듭니다.
  - **+ 책꽂이**: 번호(기본 = 마지막 번호 + 1) · 설명 · 층 수. **+ 층**: 그 책꽂이 맨 위에 한 층 추가 (층 번호는 맨 아래가 1층).
  - **구역 수정** / 책꽂이 번호 / 층 칸을 누르면 이름(설명)을 고치거나 지울 수 있습니다.
  - 지우기 규칙: 순찰 기록 · 등록 도서 · 수신함 사진이 있는 층은 지울 수 없고, 층은 번호가 비지 않도록 맨 위 층부터 지웁니다. 구역 · 책꽂이는 안의 층을 모두 지울 수 있을 때만 통째로 지워집니다(층의 기준 사진도 함께 삭제).
  - 새로 만든 층은 **도서 없음** 상태입니다. 도서 목록(정답지)은 도서관 정보 시스템에서 받아올 예정이며, 그 전까지는 `library_data.sql`에 등록된 층만 분석할 수 있습니다.

## ⚠️ 현재 알려진 제약
- **정상 이미지의 인식 누락이 ID에 영향을 줍니다.** 책 ID(`B001`~)는 "정상 이미지에서 왼쪽부터 n번째로 인식된 책"입니다. 정상 이미지에서 책이 하나라도 인식되지 않으면 그 뒤 ID가 한 칸씩 밀리고, 가상 서가 정보의 서명과도 어긋납니다.
- **분석 작업 기록은 서버 메모리에만 있습니다.** 분석 중에 서버를 재시작하면 진행 중이던 작업은 사라집니다. (완료된 결과는 DB에 남음)
- **비밀번호 변경 · 관리자 계정 관리는 명령줄(`manage_users.py`)로만** 할 수 있습니다. 서버는 HTTP로 동작하므로, 실제 배포할 때는 HTTPS(리버스 프록시 등) 뒤에 두어야 합니다.
- **판정 기준값은 임시로 정한 값입니다.** 매칭 유사도, 인식 품질 기준 등은 AI 모델의 정확도가 확정되면 실제 결과를 보고 조정해야 합니다. (`backend/analyzer.py` 상단 상수)
