# 시연 시나리오

A구역 1번 책꽂이 3층(`A-01-3`, 13권)의 사진과 RFID 리더값 묶음입니다. 사진 옆의 `.rfid.json`이 그 사진과 함께 스캔한 RFID 값이어서, 가상 RFID로는 나오지 않는 오배가 · RFID 미인식 같은 판정을 볼 수 있습니다.

## 넣는 방법
서버를 켠 뒤, 저장소 맨 위 폴더에서 실행합니다.
```bash
python backend/load_patrol_photos.py backend/test_data/scenarios/LIB001 --now
```
대시보드에서 **순찰 사진 일괄 분석**을 누르면 9장이 분석됩니다(CPU에서 약 2분 30초). 끝나면 A구역 1번 책꽂이 3층을 고르고 **순찰 이력**에서 각 결과를 엽니다. 이력은 위에서부터 최신순이라 09번이 맨 위입니다.

## 시나리오와 결과
13번 도서는 미태깅 도서라 어느 시나리오에서도 RFID에 없습니다.

| 번호 · 파일 | 사진 | RFID | 나오는 알림 |
|---|---|---|---|
| `01_normal` | 정상 서가 | 12권 전체 | 없음 (서가 정돈 완료) |
| `02_misplaced` | 정상 서가 | 전체 + 다른 층 도서 | **오배가**: 「어린이 외교관 중국에 가다」, 원래 위치 A구역 2번 책꽂이 3층 7번째 |
| `03_tag_missing` | 정상 서가 | 5번 도서 태그 없음 | **RFID 미인식**: 5번째 책 |
| `04_unregistered` | 정상 서가 | 전체 + 도서 정보에 없는 태그 | **미분석**: `XX0000000000` |
| `05_spine_hidden` | 책등 안 보임 2권 | 12권 전체 | **책등 안 보임** 2건 + RFID 후보 2권 (권수 일치) |
| `06_spine_hidden_no_tag` | 책등 안 보임 1권 | 그 책 태그 없음 | **책등 안 보임** 1건 + **누락** (후보 없음) |
| `07_upside` | 뒤집힌 책 3권 | 12권 전체 | **뒤집힘**: 4, 6, 10번째 |
| `08_stack` | 누운 책 1권 | 12권 전체 | **가로로 누움**: 8번째 |
| `09_tilted` | 기울어진 책 1권 | 12권 전체 | **기울어짐**: 3번째 |

표의 결과는 2026-11-01에 `yolo26l_1280_v3.pt` 모델로 9장을 모두 분석해 확인한 값입니다. 모델이나 AI 코드가 바뀌면 달라질 수 있습니다.

## 상태이상 (대출 중 도서 발견)
책의 자료상태를 바꿔야 해서 묶음에 넣지 않았습니다. DB에서 3번 도서를 대출 중으로 바꾼 뒤 `01_normal`을 분석하고, 끝나면 되돌립니다.
```bash
docker exec library-mysql mysql -uroot -p1234 library_ai_db -e "UPDATE BO_BOOK_TBL SET WORKING_STATUS='BOL211O' WHERE REG_NO='EM9900000003'"
docker exec library-mysql mysql -uroot -p1234 library_ai_db -e "UPDATE BO_BOOK_TBL SET WORKING_STATUS='BOL112N' WHERE REG_NO='EM9900000003'"
```
`-p1234`는 기본 DB 비밀번호입니다. 바꿨다면 그 값을 쓰세요.

## 참고
- 사진은 층 정보에 없는 다른 책을 실제로 꽂아 찍은 것이 아닙니다. 오배가는 RFID 값으로 만든 시나리오입니다.
- 분석한 순찰은 이력에 남습니다. 지우려면 `python reset_db.py`를 실행합니다. **모든 순찰 기록이 지워지니** 필요한 기록이 있으면 실행하지 마세요.
- RFID 리더값이 있으므로 이후 **배가 위치 자동 배정**은 이 층을 마지막 순찰(`09_tilted`)의 RFID로 정합니다.
